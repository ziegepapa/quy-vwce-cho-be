# MU3 — Owner member management, local rehearsal only

Base main 1625c4d8722e44cc9dddaf25f10113e19a4f9dc6 (MU2 #430 merged; Test and Deploy #1582 and Pages #449 succeeded). MU2 database candidate is still local-only; neither that candidate nor MU3 is deployed to hosted Supabase.

## Scope
- Settings panel (German/Vietnamese) lists names/email, role and invited/pending/active/revoked state; create invitation by email and confirm revocation. No member reading UI, sync scope changes, financial changes, role editor, membership activation button or MU4–MU6.
- UI is gated on both VITE_MU3_LOCAL_REHEARSAL=true and exact local Supabase URL; app must be authenticated, MFA/recovery gates satisfied. Panel controls render only after successful scoped server list. Member management is hidden for the two-account MEMBER principal, including revoked membership. Independent vault ownership under MU2 is otherwise unchanged.
- Deno service binds loopback, accepts only local confirmed synthetic caller identities and @example.invalid target emails, verifies Auth JWT and verified MFA factor requirement, checks requested ownerId equals caller id and rejects incoming member principals. List and revoke use caller JWT and MU2 RLS. Only trusted service performs scoped Auth identity lookup and INSERT of role member/status invited; no caller-provided role/status accepted. No public service-role key, no cached list, no provider email call.
- For a new synthetic address, Auth Admin generate_link type invite creates a real local identity without sending mail; returned action link/token is discarded, never returned or logged. Existing local identity is bound by normalized Auth email. Duplicate membership is rejected. Revocation PATCH only targets caller's own membership; the existing MU2 trigger sets revoked_at. Service never activates membership.
- This is deliberately **not an externally deployable invitation service**: actual email delivery, verified acceptance integration, durable idempotency/rate limiting, cross-vault/ADMIN management, orphan-identity recovery on Auth success/DB failure, and hosted migration/config review need separate approval before any real enrollment. For the rehearsal there are only two synthetic identities, bounded lookup and list. No secrets or real emails changed. No production deploy/merge authorized for this PR.
- Supabase Auth API reference: https://supabase.com/docs/reference/javascript/auth-admin-generatelink and https://supabase.com/docs/reference/javascript/auth-admin-inviteuserbyemail (generateLink does not deliver email).
