## Authorization contract

- Owner-root is the existing immutable user_id; no owner membership record or owner transfer. Five entity tables keep their owner policies and effective grants. Added SELECT for active membership, separate INSERT/UPDATE/DELETE for active ADMIN only. Owner and ADMIN must not reassign user_id (trigger). Profiles stay per-user, and private Guardian/Gemini state is untouched.
- A MEMBER may read shared rows only, including tombstones needed for sync. Member may still own/read/write their own separate vault; no access to other vaults. This is not blanket account write-lock. No role claim or user_metadata is trusted. Revocation/demotion is checked in the next request from live membership state even when JWT remains valid; it cannot erase data already copied or stop an already-running request.
- public.vault_memberships is FORCE RLS, FK to Auth users, unique owner/member pair, self-owner prohibited, lifecycle invited/pending/active/revoked. Authenticated may SELECT own membership/owner scope (active ADMIN also manages that scope), no client INSERT/DELETE/TRUNCATE. Column UPDATE role/status only, RLS owner or active ADMIN of another non-owner membership, no self-promotion, no client activation or reactivation. Owner root cannot be revoked via membership. Trusted service-role is the only creation/activation path. It is NEVER exposed to browser.
- Non-exposed mu2_private helper checks only auth.uid() for an active ADMIN in the requested owner scope, returns boolean, fixed empty search path; definer needed to avoid recursive membership RLS. No public privileged RPC. Private schema absent from Data API exposed schemas. Trigger functions are invoker and client EXECUTE revoked.
- Trusted service-side invitation/acceptance integration with Auth email, binding a verified identity and owner/admin caller before privileged insertion/activation, still required before real enrollment; this PR tests the database boundary with synthetic service fixtures, not an invitation email backend or UI. Do not use generic service-role insertion from a browser. Admin management of additional members requires expanded matrix before release.
