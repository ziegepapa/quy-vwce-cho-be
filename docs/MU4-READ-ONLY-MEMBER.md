## Model
The app selects a separate read-only surface before mounting the writable owner app. It resolves incoming membership from the authenticated Data API with the existing MU2 RLS, never from a client role flag. Exactly one active MEMBER relationship is supported by this v1 two-account rehearsal; invited/pending/revoked/ADMIN/multiple relationships or unavailable membership API fail closed. The owner app keeps its original behavior in normal builds. The sharing rehearsal is only enabled by VITE_MU3_LOCAL_REHEARSAL=true and exact loopback URL. It uses a separate writable owner Dexie database and binds that browser origin to one owner ID; a different owner must use a different browser profile. Member never mounts the writable app, accesses its Dexie/outbox or runs push/restore. Shared records are in React memory only, direct GET with current JWT/no-store, always owner-scoped, tombstones excluded and paginated. Do not substitute a local role for server authorization.

Member checks membership both before and after each snapshot, clears visible data before rechecking every 5 seconds, on hidden/offline/pagehide, on session change, error and logout. Revocation is immediate for subsequent server reads, but an already rendered view can only clear when the browser detects the change (next check at most 5 seconds while foreground and responsive). Already viewed/copied data cannot be retrieved remotely. Multiple tables are read separately, so not an atomic snapshot. No offline shared cache. The reader does not expose private notes/contact/emergency details in UI; MU2 grants existing settings rows, which can contain nested sensitive metadata; column/projection minimization needs release review before hosted sharing.

Overview, VWCE/VALL holdings, ledger and monthly history, goals, and local-only simulation controls are bilingual. Uses existing transaction replay and projection engine. Values are explicitly based on public quote feed, not owner-only manual quote preferences; missing values shown as unavailable, stale quotes labeled. Only synchronized server data is shown, not unsynced local owner edits. Simulation assumes constant planned monthly contributionY2, owner return assumption, ETF fees and latest purchase allocation; not broker Sparplan proof, before tax, not financial advice. No shared writes, settings/backup/member management or financial edits.
